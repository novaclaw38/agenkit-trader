# AgenKit Trader: Local Read-Only UI Spec

Date: 2026-10-22. Status: approved design.

## 1. Purpose

A local, read-only web page to inspect the agent: what it is doing, what it decided, what research found, which limits are active and how the system could fail. It shows only numbers that exist in files. It controls nothing.

## 2. Hard constraints

- `agenkit ui [--host 127.0.0.1] [--port 8765]`. Binds 127.0.0.1 only: any other host is refused (exit 2) before a socket is opened.
- Stdlib `http.server` only. No background threads, no external CDN, no keys, no environment-variable key reads.
- GET only: every other method returns 405. A fixed whitelist of routes; anything else (including path traversal) is 404. No file path comes from the request.
- The Host header is checked on every method: only `127.0.0.1` or `127.0.0.1:<bound port>` is served, anything else gets 421 with no data (DNS-rebinding guard).
- Every request re-reads its files from disk. A log over 8 MiB is read from its tail only; the page then says "log truncated, showing recent records" and shows paper days/trades, positions and mode as unknown rather than computing them from a partial log. Responses carry `Cache-Control: no-store`.
- The `agenkit_trader.ui` package never imports execution, exchange, runtime-loop, kill-switch or risk-gate modules (tested in a fresh interpreter). It imports config loaders and `live_unlock` (`PaperStats`, `paper_stats_from_log`) read-only; those pull in only the pure `execution.venue` dataclasses.
- NaN/Infinity in research JSON becomes n/a per field. Missing or corrupt files give a short message in the page (no stack trace, no file path). Log-derived text is HTML-escaped in the browser; the page also sets a CSP.

## 3. Routes

`/` (page), `/api/status`, `/api/decisions`, `/api/research`, `/api/risk`, `/api/failure`.

## 4. Tabs

1. **Status**: mode (research-only / paper / halted, with the halt reason), positions and stops, last decision time with a stale warning, live-gate state (locked / thresholds met, never "unlocked": live order placement is not implemented in this build; paper days and trades against `config/live.yaml` thresholds), and an inline-SVG equity and drawdown chart only when there are 2 or more data points. Auto-refresh every 30 s on this tab only.
   - The state file holds no positions. Positions and stops are derived from the decision log (net filled quantity, last placed stop) and labelled as such, not as exchange state.
   - Equity points are the `state.equity` logged with each order; drawdown is computed from them. An empty log shows "no paper trades yet".
2. **Decisions**: filterable table (time, kind, symbol, signal, action, gate verdict or reject reason, client id, fee). Fees are shown as logged ("fee unknown"); funding is not logged and says so. Newest 1000 records.
3. **Research**: candidate table from `research/REPORT.json`, trial counter from `trials.json`, policy label (`research` when the entry has no `policy` key), deployed panel (empty: "nothing passed the gate"). Every metric is labelled hold-out and the trial count sits next to it.
4. **Risk**: active limits from `config/risk.yaml`, `runtime.yaml`, `gate.yaml`, `live.yaml` and `symbol_rules.yaml`.
5. **How could this fail**: section 12 of the main design spec, verbatim.

## 5. Mode and staleness

- halted: state file `halted` set, or the log's latest `kill_switch`/`halt` has no later `runtime/halt_reset`.
- paper: otherwise, if the log has a `runtime/started` record. research-only: otherwise.
- stale: the last log record is older than 2 hours (1h bars plus margin).

## 6. Not in scope

Writing anything, controlling the runtime, live trading, authentication (loopback only), profit headlines.
